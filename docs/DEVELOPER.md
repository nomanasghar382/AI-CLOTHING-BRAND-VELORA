# Developer Guide

## Repository layout

```text
backend/
  app/Contracts          Repository interfaces
  app/Repositories       Eloquent implementations
  app/Services           Business logic
  app/Http/Controllers   Versioned API controllers
  app/Http/Requests      Validation
  app/Http/Resources     API transformers
  routes/api.php         REST routes under /api/v1

frontend/
  src/components         Reusable UI
  src/pages              Route screens
  src/context            Global state
  src/services           Axios API clients
  src/hooks              Shared hooks
  src/utils              Offline cache and helpers
```

## Conventions

- API responses use the standard envelope: `success`, `message`, `data`, `errors`, `status`, `timestamp`
- React uses JavaScript (no TypeScript) and the existing VELORA design tokens
- External integrations (OpenAI, Stripe, Cloudinary, weather) are configured in Laravel `.env` only
- Ethical passport data must come from verified database records only
- AI recommendations must reference active in-stock catalog products only

## Local workflow

1. Start Laravel: `php artisan serve`
2. Start Vite: `npm run dev`
3. Run migrations after pulling: `php artisan migrate`
4. Seed demo data: `php artisan db:seed`

## Testing

```bash
cd backend
php artisan test

cd frontend
npm run lint
npm run build
```

Feature tests live under `backend/tests/Feature/Api/V1`.

## Adding an API endpoint

1. Add route in `backend/routes/api.php`
2. Create or extend a controller under `app/Http/Controllers/Api/V1`
3. Put business logic in a service class
4. Use Form Requests for validation and API Resources for responses
5. Add a feature test

## Adding a React screen

1. Create page under `frontend/src/pages`
2. Register route in `frontend/src/routes/AppRoutes.jsx`
3. Add service methods in `frontend/src/services`
4. Reuse existing layout, design tokens and feedback components

## PWA development

The service worker is generated by `vite-plugin-pwa` during `npm run build`. Offline fallback is `/offline`. Runtime caching covers catalog APIs, Cloudinary assets and account endpoints.

## Search and filters

- `GET /api/v1/search` — ranked instant search
- `GET /api/v1/search/suggestions` — suggestions, popular and recent terms
- `GET /api/v1/catalog/filters` — dynamic filter metadata

Search synonyms are seeded via `SearchSynonymSeeder`.
